# 1.Pending

**This is a common problem which is  Pods Pending that usually caused by several specific factors. In this blog post, we’ll give a brief summary**

I.lack of GPU

write a YAML file.

```jsx
apiVersion: apps/v1
kind: Deployment
metadata:
  name: gpu-batch
  namespace: gpu-lab
spec:
  replicas: 5
  selector:
    matchLabels:
      app: gpu-batch
  template:
    metadata:
      labels:
        app: gpu-batch
    spec:
      nodeSelector:
        accelerator: nvidia-a100
      containers:
      - name: trainer
        image: busybox:1.36
        command: ["sh", "-c", "sleep 3600"]
        resources:
          requests:
            cpu: "1"
            memory: 1Gi
            nvidia.com/gpu: "2"
          limits:
            cpu: "1"
            memory: 1Gi
            nvidia.com/gpu: "2"
```

Total apply  10 GPU, execute YAML,the result is follow.

![image.png](/images/1.Pending/image.png)

A pod is in pending status. Next,check the reason

```jsx
kubectl describe node gpu-node-a100  /check the numb of gpu under this node 

kubectl describe pod gpu-batch-778979f58d-f74wv -n gpu-lab / check detail information,the key part is Event
```

II 

execute:

```jsx
kubectl taint node gpu-node-a100 gpu=production:NoSchedule  /add Tiant for gpu-node-a100
```

![image.png](/images/1.Pending/image-1.png)

create YAML and execute:

```jsx
apiVersion: v1
kind: Pod
metadata:
  name: gpu-taint-pending
  namespace: gpu-lab
spec:
  restartPolicy: Never
  nodeSelector:
    accelerator: nvidia-a100
  containers:
  - name: trainer
    image: busybox:1.36
    command: ["sh", "-c", "sleep 3600"]
    resources:
      requests:
        cpu: "1"
        memory: 1Gi
        nvidia.com/gpu: "1"
      limits:
        cpu: "1"
        memory: 1Gi
        nvidia.com/gpu: "1"
```

![{ED97F9AA-A696-44D4-B548-93FFA19A3666}.png](/images/1.Pending/ED97F9AA-A696-44D4-B548-93FFA19A3666.png)

check reason:

![image.png](/images/1.Pending/image-2.png)

add tolerations in pod YAML , submit against 

```jsx
tolerations:
- key: "gpu"
  operator: "Equal"
  value: "production"
  effect: "NoSchedule"
```

![{A470F0E4-041D-4C79-99A8-8586DA06F1C8}.png](/images/1.Pending/A470F0E4-041D-4C79-99A8-8586DA06F1C8.png)

Summary:The gpu-node-a100 has 8 GPUs with sufficient resources. The Pod requests 1 GPU, which is a reasonable resource request. However, the node has a taint `gpu=production:NoSchedule`, and the Pod does not have corresponding tolerations. Therefore, it cannot be scheduled

### III:

Edit YAML:

```jsx
nodeSelector:
  nvidia.com/gpu.topology: nvlink-a100
```

apply and verify the results

![image.png](/images/1.Pending/image-3.png)

can be seen `node(s) didn't match Pod's node affinity/selector` 

The Pod requires specific GPU topology labels, but the node does not have them.

Repair the Labels and observe.

```jsx
kubectl label node gpu-node-a100 nvidia.com/gpu.topology=nvlink-a100
```

![{D029F476-EB3E-4069-9CBC-C6821D1621CE}.png](/images/1.Pending/D029F476-EB3E-4069-9CBC-C6821D1621CE.png)

The Pod requires `nvidia.com/gpu.topology=nvlink-a100`, but the nodes do not have this label. Therefore, the scheduler excludes all nodes, and the Pod remains Pending.
